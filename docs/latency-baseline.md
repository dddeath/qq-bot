# 固定回复与 dot 延迟采样

## 采样安排

由主控在原绑定群、原群 dot 聊天组织固定回复与 dot 简短回答交替各 5 条。每条使用主控提供的唯一文本，用户手动发送；上一条实收或等待满 120 秒后至少间隔 30 秒。失败、超时不补样，迟到回复单列。本轮不搜索，不改模型、聊天设置、订阅或发送策略。

真实采样前，由主控确认运行进程已加载本轮提交。不要同时启动固定探针与桥接接收器。保留原配置与服务状态；一条采样结束后停止对应有界接收器，再切换下一条。复用 `qq-probe/group-reply-run.mjs` 的 `runGroupReplyCommand({expectedText, timeoutMs:120000})` 和既有桥接管理入口；接收器运行窗口不替代用户发出消息后的实际等待记录。主控在等待上限停止接收器，保留此前快照，不自动重发。

## 原始记录

每条样本保存实际命令、退出状态、运行提交和原始结果。dot 使用管理入口 `/qq/group/status` 的返回对象，不使用含订阅密钥的 `state.json`。固定回复使用 `runGroupReplyCommand` 产生的 JSON。记录保存在本机忽略目录 `.local/` 或 `evidence/`。

输入 JSON 顶层为 `samples` 数组，按发送顺序排列，每项字段如下：

| 字段 | 内容 |
| --- | --- |
| `id` | 唯一样本编号 |
| `mode` | `fixed`、`dot`；既有搜索参考用 `search` |
| `group_openid` | 绑定测试群 ID |
| `started_at` | 本机记录的该条等待开始时间，带时区 ISO 时间 |
| `deadline_at` | `started_at` 后 120 秒 |
| `observed_at` | 保存该结果快照的本机时间 |
| `ended_at` | 本机记录的实收或等待上限时间，用于核对条间间隔 |
| `measurement_version` | 实际运行提交、命令、退出状态等对象；缺失报告为 null |
| `fixed` | 固定探针完整结果对象（仅 fixed） |
| `dot` | `/qq/group/status` 返回对象（dot/search） |
| `message_id` | 本条桥接消息 ID（dot/search）；未接收到消息时可缺失 |
| `timed_out` | 等待上限时已判超时则填 true；后续迟到记录仍保留 true |
| `client` | 可选 `{sent_at, received_at, same_clock:true}`；仅确认收发时间来自同一客户端时钟才填 true |

客户端时间只在客户端内相减，不减本机时间或 QQ 事件携带的时间。缺失字段输出 null，表示未知；旧版本缺少投递开始或成功读取标记时，对应阶段保持未知。`mcp-http` 成功读取只证明 MCP 入口读到了本条消息，实际调用者仍由主控结合原群 dot 运行核验。

## 离线生成报告

在仓库根目录执行：

```powershell
node E:\qq-bot\scripts\latency-report.mjs E:\qq-bot\.local\latency-input.json E:\qq-bot\evidence\latency
```

命令只读取记录，不连接 QQ、不唤醒 dot、不发送消息。标准输出为本轮独立目录，内含原文 `raw-input.json` 与 `report.json`。每次生成新时间戳加随机后缀目录，保留此前产物。输入错误退出非零。

已提供的本机接收时间须位于本条采样窗口内且不晚于快照；完成时间须不早于采样开始及接收时间，并且不晚于快照。矛盾记录使命令非零退出，不生成成功报告。窗口内接收、截止后完成且快照已包含该完成记录的回复仍记为超时，迟到时间单列；缺失时间点仍标记未知。客户端时间不参与这些跨端比较。

报告区分：

- `local_ms`：本机接收至 QQ 确认；迟到确认仍可保留时长，但不进入成功样本统计。
- `client_ms`：同一客户端实际收发耗时；未知时总体目标保持证据不足。
- `stages`：接收至投递、投递请求、重试等待、等待首次成功消息读取、读取至回复调用、QQ 请求；固定探针收尾及发送前开销单列。
- `groups`：每组总数、成功、失败、超时、待定，以及成功样本中位数和最慢值。不计算 P95。
- `local_target` / `target`：分别判断本机主计时和包含客户端证据的十秒目标。达到只描述本组 5 条完整样本；失败、超时或超过十秒时为未达到，不证明持续性能。
- `comparison`：核对同群、交替顺序、数量和条间间隔；相近运行环境由主控核对。
- `investigate`：指出现有分段中位数最大的阶段，供下一步检查；不将等待直接归为模型思考，不自动调整运行策略。

## 恢复与代码回滚

离线报告命令不修改服务状态。真实采样后由主控停止临时接收器，按采样前记录恢复服务状态；不删除订阅、发送账本、原始记录或旧证据。新增观测仅增加时间和读取成功字段，旧状态仍可读取。代码回滚使用本工单实现提交的 `git revert <提交号>`，保留其他工单提交；重启服务须由主控安排。真实群验收与工单关闭由主控完成。
