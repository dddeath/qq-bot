# 每日学习与原生轨迹

每日学习使用独立会话与配置，从聊天材料、已完成检索及固定创作者内容中生成待审核结果。学习输入、运行记录、审核资料与发布正文分开保存，领域知识库按需读取。

视频学习先获取标题、作者、分节和简介，再在预算内组合字幕、评论、弹幕与实际画面。定向读取围绕当前目标，探索可以发现新线索；探索转定向记录与目标的关联依据。预算配置见 `config/video-reading-policy.json`。

每日回放可对阅读任务追加有界补读并评估目的偏差、探索不足和定向不足；参数建议记录在结果中，不自动改变线上配置。

`src/runtime/native_reading_traces.py` 汇集原生子代理调用、返回、耗时和当时的读取目的；实际返回的图片块落盘并关联调用标识。缺失目的、结果或图片转换失败保留状态，不补猜。每轮证据使用独立目录。

`src/runtime/latency.py` 与 `latency_detail.py` 统计消息、模型、工具和发送回执阶段。重叠调用不能直接相加为端到端时间；缺少的时间保持未知。

## 独立回放检索

回放由独立学习会话直接调用只读资料工具，不依赖主聊天派出子代理。`learning_research.py` 从原调用参数中提取 BV 候选；旧记录缺少 `video` 字段仍可重查，但不据此补写旧读取目的。

模型先读取基础概览，再自行选择网页搜索、B 站字幕、评论及楼中楼、弹幕、视频画面和外部图片。工具通过 `learning_research_mcp.py` 开放，沿用已有资料服务，不开放 QQ 写入工具。每次调用携带本次读取目的和理由。

预算读取 `reading_review`：基础概览最多 3 次；其余资料读取共享 `max_read_units`，其中定向补读最多 18 次，探索调用受 `exploration_budget_ratio` 限制，失败也计数。任务总额度低于 18 时，定向仍受该总额度限制。`per_record_timeout_seconds` 默认 480，每条记录独立计时，覆盖该条补读和评审；`extension_seconds` 默认 150，实际补读上限取它与该条剩余时间一半的较小值，剩余时间用于评审。一条失败或超时后，下一条仍获得完整的单条预算。旧 `reading_review.timeout_seconds` 为已停用的整批时限，不映射为单条时限；迁移时删除该字段并显式填写新参数。执行器内部的 `timeout_seconds` 仍表示宿主实际分配的阶段时限。原 JSON 决策循环的 `max_decisions` 不用于原生工具会话。原生网页读取先通过 `declare_native_read` 预留同一预算；运行器检测未预留搜索后终止本轮，保留实际事件。

补读协议要求先查看原目标、停止结论与群回复／评价关联，选定具体核验点，再按相关性展开证据。证据阅读也计时，时间不足时用已有材料收尾。宿主因时间到期终止进程时，回执为 `execution_status=timed_out`、`status=partial`，保留真实退出码和已取得材料；退出码为 0 不覆盖超时原因。正常完整完成需要有效的停止声明及完整工具结果。

`watch_video` 首次准备及后续查询使用独立账本：每视频最多 10 次、从首次准备起最多 180 秒，且受任务总时间限制；不占定向或探索补读次数。采样和图片读取仍计补读。返回 `video_polls` 提供各视频剩余次数及时间；达到上限后保留未就绪状态，用已取得材料收尾。

共享协议要求核心结论形成后评估未展开材料的探索价值。可以读取少量旁支材料，也可以在停止原因中说明跳过探索的依据；探索后转定向保留与原目标的关联。

每轮保存输入、实际命令、工具参数与返回、图片、读取目的、耗时和模型执行日志。评审图片按需返回真实像素。原始轨迹不变，缺失的历史依据仍标为未知；评审建议不自动应用。

## 检索工具入口轨迹

只读检索服务的冻结工具配置可设置 `reading_trace`，字段为 `root`、`scope`、`max_read_units`、`exploration_budget_ratio`、`timeout_seconds`。同一任务跨服务使用相同根目录和 task_id；`scope` 对应每日评审的 `audit_scope`。未配置的服务保持原调用契约。

`tool_proxy.py` 为此类服务提供 `begin_reading_task` 和 `finish_reading_task`，读取工具增加 `_reading` 参数，用于记录调用前的目的、理由、目标关联和上一轮观察。代理剥离该参数后调用原服务，将真实结果、图片、耗时和剩余预算写入 `research_trace.py` 管理的独立任务目录。关闭任务后停止接受新读取。

任务目录包含 `context.json`、共享预算 `budget.db`、逐次 `read-NNN.json` 与图片、`completion.json` 和供学习读取的 `report.json`。未结束任务的停止原因留空。该报告明确标记覆盖范围为已接入的 MCP 调用；原生网页搜索及未接入工具仍依赖原生轨迹采集，不能据此报告声称覆盖整条检索过程。

## 评审输入与完成状态

独立补读与最终评审首次只获得材料目录位置和任务提示。`review_materials.py` 将完整原记录写入内容寻址材料库，相同内容块只存一份；原字段、调用顺序、重复调用和精确文本仍可重建。原始报告原件保持不变。

材料目录包含 `index.json`、`materials.sqlite3`、`images.json` 和按内容摘要存储的图片。`list_review_materials` 列出章节与读取记录，`read_review_material` 按材料 ID、JSON pointer 和游标展开，每次正文最多 6000 字符，`next_offset` 可继续取得完整内容；`read_review_image` 读取目录中的实际图片。缺图明确返回缺失。每次读取的参数、返回内容或图片摘要、时间写入 `access/`。

`reading_review.max_input_chars` 不再用于拒绝整份评审材料。逐次披露控制单次输入体积，模型按需选择内容；原证据读取不计联网补读次数，仍受评审总时限限制。三个评分缺少依据时保留空分数和限制说明。`review_model.py` 保留实际启动命令、模型输入、输出和执行状态。

每个任务的 `assessment_complete` 仅在目的偏差、探索不足、定向不足三项均获得有效评分时为真。全部入选任务均完成后，批次 `all_assessments_complete` 才为真；空批次、选样失败、入选任务执行失败和缺项评分均不满足验收。未入选记录单独列出，不计为评审失败。

## 检索报告、群回复与后续反馈

`research_feedback.py` 只读汇集指定运行目录的 `timed.jsonl` 与当前群的 `chat_inbox`，生成独立审核材料。子代理报告以原生线程和轮次标识区分；发送结果以 QQ 消息 ID 去重，只收录成功回执。分条发送逐条保留，部分成功时保留已经发出的部分。

一个回应轮次只交付了一份报告时，记录该报告与本轮发送回复的关联。该依据证明报告已交付，内容是否被采纳由评审对照原文判断。多报告并行或缺少报告记录时保留待核验状态。原请求从发送回执的 `reply_to_event_id` 查回，缺失时留空。

后续消息引用已发送消息，或完整引用其正文时，保存原文、发言者、时间、引用目标及证据位置。其余窗口内无明确引用的消息放入 `pending_followups`，不直接视为评价。消息是否构成评价、补充条件或其他话题由评审判断。已存在的 `user_evaluation` 原文保持不变。

每日和单次评审共用反馈采集入口。`reading_review.feedback` 配置 `enabled`、`run_directories`、`session_id`、`window_seconds`（默认 3600）和 `native_sessions_directory`；后者未填写时取当前 `CODEX_HOME/sessions`。`current_run_path_file` 可指向当前运行目录的指针文件，每批重新读取；`run_directories` 可同时提供该批涉及的历史运行目录。消息读取使用学习任务的 `access_db`、账号和群，worker 将这些绑定传入同一入口。离线回放可配置 `cutoff` 固定采集截止时间，或用 `reading_review.feedback_bundle` 引用已保存材料。

反馈写入评审输出目录下独立命名的 `feedback/feedback-*.json`，并记录采集状态。未配置和采集失败分别标记 `not_configured`、`collection_failed`，评审材料保留缺失原因。分页交付的子代理报告按当前群、报告 ID 和版本，从对应运行目录的 `research-links.sqlite3` 只读恢复完整内容；原版本未取到时标记正文缺失，不把分页片段当作完整报告。

审核投影使用原生线程与轮次关联阅读记录；执行器报告只有 `task_id` 时，通过该任务的原生工具成功回执定位到已交付报告的唯一轮次，保留调用 ID 和来源行号。多个候选保留歧义状态；群范围不符或身份缺失时返回明确状态。原阅读记录、群消息、知识库和线上参数均不被改写。后续消息窗口与采集截止时间写入材料，窗口外的反馈不在本轮覆盖范围内。

## 回放选样与单条预算

`reading_review.max_tasks` 默认 3，可配置为 1–3。候选数不超过上限时全部进入评审，不启动选样模型。超出上限时，模型先读取候选目录，按需展开原请求、轨迹及已关联反馈，自主选择最多规定条数，并输出每条选择理由及执行顺序。

`selection_timeout_seconds` 默认 120，独立于每条 480 秒预算。选样复用评审模型和只读材料工具，完整原记录保存在材料库，首次模型输入仅包含目录位置、任务要求与预算。候选目录提供原请求预览、时间、类型、完成状态和反馈状态；长原请求按需读取完整内容。

`selection/catalog.json`、`selection/answer.json` 和 `selection/receipt.json` 保存候选、模型返回与验证结果；模型执行日志和实际输入保存在 `selection/model/`。重复或越界 ID、空选择、缺少理由和超时均作为选样失败记录，不自动改用前几条。未选记录标为 `not_selected`，不自动加入后续批次。

批次报告分别统计 candidates、selected、completed、incomplete、unselected，并保留逐条耗时和选择状态。三条评审预算最多合计 1440 秒，加选样上限为 1560 秒；反馈汇集、文件写入及进程收尾另有开销。补读次数、探索比例、学习发布规则与聊天运行状态保持原配置。

配置样例见 `config/examples/reading-review.json`。
