# 话题维护仅辅助发送前过期检查

主聊天的回复依据保持与 Tulpa 原始输入一致，包括消息顺序、发送者、@、引用、图片和原生上下文。主聊天自行判断话题归属、发言对象、交流意图及回应方式。

后台维护者只提供消息间话题关联，用于放宽普通新消息引起的过期判定。其输出不进入主聊天输入，不筛选消息，不决定是否回应，不成为回复规划的前置条件。

在线撤出话题管理工具、维护者回应概率、回应队列和维护完成唤醒。原始 wait/get、plan、表达选择、send 流程保留。批量话题管理和发送后附带队列目标不再实施。

内部关联缓存最多5组，10分钟无更新回收，总记录和每组均限制数量、年龄、字数；这些限制不改变主聊天的原始消息输入。容量不足时可淘汰关联缓存；未知关联沿用原生过期检查。维护者使用订阅 gpt-6-luna / low / Fast，只判断话题关联。

原生读取快照45秒内放宽普通新消息检查。超过宽限，仅在已知关联表明新增消息均属其他话题时放行；同话题或未知则读取最新完整消息，由主聊天判断回答是否仍适用并重新规划。撤回、停止、权限、连接、冷却及未知发送结果规则保留。

人设、学习、知识库、其他工具和原生线程保持。历史回放实现与证据保留，但其中的旧队列规则不作为当前在线行为。以原始输入交付和发送前检查两个接口验证，不用离线通过代替真实群收件。
