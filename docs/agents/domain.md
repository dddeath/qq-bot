# 领域文档

本仓库采用单一上下文布局：

- `GLOSSARY.md`：项目术语表。
- `docs/adr/`：架构决策记录（ADR），记录已确定的重要设计选择。

## 探索前的读取规则

探索代码前，读取根目录的 `GLOSSARY.md`，以及 `docs/adr/` 中与当前任务有关的记录。

文件或目录不存在时，直接继续，不将其缺失列为问题，也不提前建议创建。由 domain-modeling 技能在术语或设计决策实际确定后按需创建。

## 使用项目术语

任务标题、修改建议、假设和测试名称中的领域概念，采用术语表定义的名称，避免使用术语表明确排除的同义词。

遇到术语表未收录的概念时，先检查是否引入了项目并不需要的新名称；确有缺口时，在后续领域建模中补充。

## 说明决策冲突

建议与已有架构决策冲突时，明确指出对应记录及重新讨论的理由，不静默覆盖既有决策。
