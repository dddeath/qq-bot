# Tulpa 发送前话题检查

主聊天沿用 Tulpa 原始完整输入、原生上下文、人设、学习和工具，自主判断发言对象、交流意图及是否回应。话题关联仅在后台辅助放宽普通新消息导致的过期检查。

## 在线链路

- Tulpa 接收器保存消息并原样向主聊天交付。后台维护者独立接收一份有界文本窗口，不修改交付游标、消息内容或批次。
- `gpt-6-luna / low / Fast` 仅返回已有话题编号、明确新话题或未知；不判断搭话，不创建回应队列，不向主聊天注入结果。
- 内部关联缓存最多5组，10分钟无更新回收；满额替换最旧关联。丢失或未知关联只恢复原生检查，不丢弃主聊天消息。组内和总记录的数量、时间、字数上限均参数化。
- 原生读取快照45秒内放宽普通新消息的过期检查。超过宽限，仅在目标和所有新增消息均有已知、不同的话题关联时放行；同话题或未知则由 Tulpa 提示补读。
- 主聊天使用原始 get/wait 读取最新完整内容，自行判断回答是否仍适用并重新规划。撤回、停止、连接、权限、冷却及发送回执规则仍由 Tulpa 执行。
- 维护者失败、未完成或服务重启不会阻塞原始读取与回复规划；宽限外关联不足时沿用原生检查。

## 配置

`QQ_TOPIC_SETTINGS` 指向服务器 JSON；在线必须显式设置 `mode: freshness_only`：

```json
{
  "mode": "freshness_only",
  "group": "1000000011:group:2000000001",
  "state": {
    "stale_grace_seconds": 45,
    "max_topics": 5,
    "idle_seconds": 600
  },
  "evidence_root": "/absolute/path/to/new-evidence"
}
```

`state` 还接受 `group_limits`、`topic_limits`、`message_chars`。历史回放的参与概率不在此在线模式生效。运行环境保留 Codex 订阅鉴权；不新增主聊天工具，旧三个话题工具从在线白名单移除。完整聊天规则见 `qq_tools.md`。

## 证据与验证

后台关联追加到每个接收会话的 `associations.jsonl`；每次模型调用保留独立目录，错误写入 `errors.jsonl`。旧队列和回放证据保留为历史，不恢复为待发送任务。

`verify_topic_live.py --source <未安装话题补丁的Tulpa源码副本> --output <证据目录>` 每次创建独立时间戳目录。隔离测试验证真实 MCP 输入和发送路径，QQ及模型端点使用替身；不发群消息。源码补丁回滚后逐字节比较原文件。连续两轮保留各自产物并确认前轮不变。

服务部署保存原运行文件、配置和启动信息。回滚先停止当前聊天和 Tulpa，恢复本轮备份，再恢复原线程；不删除任何历史证据。隔离验证和真实群收件分别验收。
